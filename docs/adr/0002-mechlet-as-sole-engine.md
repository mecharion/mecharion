# ADR-0002: mechlet 为唯一执行引擎，mechd 为协调层

- **状态**：已接受；**「决策」一节中「mechd 可选」的措辞已被 [ADR-0026](0026-standalone-runs-mechd.md) 修订**
- **日期**：2026-08-01
- **相关**：[ADR-0001](0001-agent-based.md)、[ADR-0014](0014-no-ha-in-v1.md)、[ADR-0026](0026-standalone-runs-mechd.md)

> **修订说明（2026-08-02）**
>
> 本 ADR 原称「mechd 是**可选**的协调层，单机形态下 mechlet 从本地文件读期望状态」。这个描述隐含了「单机不需要 Web UI 与审计」这一从未论证过的前提，而该前提站不住。
>
> [ADR-0026](0026-standalone-runs-mechd.md) 将其修订为：
>
> > **mechd 不是「可选」，而是「可以与 mechlet 同机」。** 边缘单机是 mechd + mechlet 的同机部署，功能与多节点完全一致。
>
> **本 ADR 的三条结论全部保留且更强**——避免两套执行路径、控制面故障不影响业务、边缘不是降级模式。修订的只是「单机如何获得期望状态」这一层：不再是本地文件，而是同机的 mechd。执行引擎仍然只有 mechlet 一个。

## 背景

Mecharion 必须同时服务两端：

```
中心化数据中心（数百节点、mechd 集中管理）  ←→  边缘离线单机（1 节点、无控制面、U 盘交付）
```

问题是：这两种形态在代码层面应该是什么关系？

## 候选方案与调研

### 方案 A：中心化为主，边缘为「离线降级模式」

控制面持有全部逻辑，节点代理只是执行器。离线时进入一个功能受限的旁路。

- ❌ 必然出现**两套执行路径**，行为差异会长期制造 bug
- ❌ 边缘用户拿到的是「阉割版」，而边缘恰是本产品的重要场景
- ❌ 每加一个功能都要在两条路径上各实现一次

### 方案 B：边缘单机为基准形态，中心化在其上叠加

节点代理功能完整（读期望状态、解析 Pack、物化、调和），控制面只提供集中存储、编排与界面。

- ✅ 一份执行逻辑
- ✅ 控制面故障不影响节点自治
- ❌ 控制面能做的事受限于「必须能表达为节点本地的期望状态」

调研对照：

| 系统 | 做法 | 结果 |
|---|---|---|
| **Kubernetes kubelet** | 支持 static pod：读本地目录即可运行，不需要 apiserver | 单节点/边缘发行版（k3s、MicroShift）得以存在 |
| **Puppet** | `puppet apply`（本地）与 `puppet agent`（连 master）共用同一套 catalog 应用逻辑 | masterless 部署是一等用法 |
| **Salt** | `salt-call --local` 复用同一 state 引擎 | 同上 |
| **Cloudera Manager** | Server 强绑定，agent 无独立能力 | **无法用于单机或离线场景**——这正是要避免的 |

## 决策

**采用方案 B。**

- `mechlet` 是**唯一的执行引擎**：资源调和、Runtime 驱动、generation 管理、健康检查、漂移检测全部在它内部
- `mechd` 是**协调层**：期望状态存储、blob 存储、放置解析、参数与拓扑渲染、Rollout 编排、API、Web UI
- 两种形态共用同一份 reconciler、同一份 Pack 解析器、同一份资源引擎

> **已被 ADR-0026 修订的部分**：原文此处写的是「mechd 是**可选**的协调层」「单机形态下 `mechctl --local` 经 unix socket 直连 mechlet」。
>
> 现改为：**单机形态是 mechd + mechlet 同机部署**，mechd 经 unix socket 向 mechlet 下发规格；`mechctl` 连 mechd，`--local` 退化为「mechd 不可达时的本机只读诊断入口」。
>
> 这一修订**强化**而非削弱了本 ADR 的立论：连存储与 API 层都不再分叉。

## 理由

**如果边缘是降级模式，就必然有两套代码。** 这是唯一真正重要的理由——两套执行路径在这类系统中会持续产生难以复现的行为差异，且成本随功能数量线性增长。

反过来设计的代价则小得多：mechd 的能力被限制为「必须能表达为节点本地期望状态」，而这恰好是一个健康的约束——它阻止了控制面变成一个包含隐式逻辑的黑盒。

## 后果

### 收益

- 一份执行逻辑，行为在两种形态下必然一致
- 控制面不在数据面上：mechd 故障时节点继续自愈，业务不受影响
- 这是 [ADR-0014](0014-no-ha-in-v1.md)（v1 不做 HA）能够成立的前提
- 边缘用户获得完整能力，而非阉割版

### 代价

- **跨节点协调能力受限**：任何需要节点间实时协商的功能（如分布式锁、跨节点事务）都无法自然表达，必须由 mechd 在下发前解析成各节点的本地期望状态。跨角色拓扑引用（`topology.role('primary')`）就是这样处理的——放置先于渲染，mechlet 收到的是拓扑快照。
- **mechlet 二进制更大**：它包含了 Pack 解析、模板渲染、全部资源类型与 Runtime 实现。以静态单二进制、不引入数据库（[ADR-0013](0013-mechlet-no-database.md)）等方式控制体积。
- **mechd 无法「立即推送」到断连节点**：命令需排队等待重连。对 ALM 场景可接受。
