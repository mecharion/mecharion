# ADR-0037: 单一 admin 账号、首访初始化，登录即全权

- **状态**：已接受
- **日期**：2026-08-07
- **相关**：[ADR-0015](0015-offline-first-hermetic.md)、[08-security §4](../design/08-security.md)

## 背景

M8 的 Web UI 需要认证——浏览器没地方放 CLI 那个 admin token。

[08-security §4](../design/08-security.md) 早就画过权限模型的草稿：

- RBAC 授权到 **Site 级**
- 角色划分：`viewer` / `operator` / `admin`
- Pack 发布权限与部署权限分离

但那三行从来没有实现过。UI 一旦有登录框，「谁在操作」就必须有答案——
而现在审计记的 actor 是 token，不是人。

## 候选与调研

| 项目 | 做法 | 代价 |
|---|---|---|
| **Prometheus** / **Traefik dashboard** | 不做认证，要求前面挡反向代理 | 边缘门店没有反代，等于默认裸奔 |
| **Syncthing** | 可选 basic auth，默认关 | 同上 |
| **Cockpit** | PAM，登录**系统用户** | 与「不建 mecharion 用户」的既有决定冲突；且 mechd 那台的系统用户不代表集群权限 |
| **Portainer** | 自建用户体系 + JWT | 要做用户表、口令哈希、找回流程 |
| **Grafana** | 自建用户体系 + session cookie（+ OIDC） | 更重 |

## 决策

**只有一个固定的 `admin` 账号，口令在首次访问 UI 时由本人设定，登录即全权。**

| 做 | 不做 |
|---|---|
| 单一 `admin` + 口令（argon2id） | **多用户** |
| 首次访问 UI 时初始化 | Site 级授权 |
| **PoW + 滑块** + 登录限流 | 角色划分（viewer / operator / admin） |
| HttpOnly session cookie | OIDC / LDAP / SSO |
| 审计 actor 记到 `admin` | 口令找回、邮箱、多因素 |

**首次访问 UI 时初始化，不用 `mechctl user create`。** 目标是**无人值守
部署**：离线场景下部署脚本自动装完工具与组件包，人只在最后打开一次浏览器
就拿到管理能力。要求先 SSH 上去敲命令，等于把那条自动化链断在最后一步。
口令由本人当场输入，因此也不存在「生成的口令怎么安全送达」这个问题。

**不做多用户。** 没有角色划分的多用户，在**权限隔离**上等于零——所有人都是
全权。它真正能提供的是**问责**（审计记到人）与**凭据生命周期**（离职删一个），
而这两项的价值要等角色做出来之后才成立。现在做等于先付复杂度、后拿收益。

**不预留角色字段。** 现在建一个只有一个取值的 `role` 列，等于替将来挖坑：
真要分角色时，表结构、接口、审计、UI 都得重来一遍，而那个空字段只会在
中间这段时间制造「看起来支持其实不支持」的错觉。

**登录防护用「PoW + 滑块」两层，不用传统图形验证码。**

调研的结论对图形验证码不利：2026 年商用求解服务对图像验证码**亚秒级、
成功率约 99%**，文字扭曲类已经失效，Cloudflare Turnstile 干脆放弃了图像挑战。
自绘一个扭曲文字验证码，等于做一个只挡住人、挡不住机器的门。

| 方案 | 机制 | 结论 |
|---|---|---|
| **ALTCHA** | PoW，Argon2/Scrypt **内存硬**，压制 GPU/ASIC | 协议简单可自实现，选它的思路 |
| **Cap** | PoW，SHA-256 | SHA-256 对 GPU 友好，成本压制弱于内存硬 |
| **mCaptcha** | PoW，可变难度 | **AGPL**，与本项目 Apache-2.0 嵌入有摩擦 |
| **Anubis** | 反代层 PoW 挡 AI 爬虫 | 不是表单验证码，形态不对 |
| 传统图形 | 文字扭曲 | 对自动化基本无效，且排除视障用户 |

**PoW 做真实防护**（Argon2 内存硬难题，服务端出题、一次性核销），
**滑块做可见的人机信号**。要说清楚它们的分工：

- **安全性来自 PoW**——它不验证「你是人」，而是**给每次尝试标价**，
  且不参与 AI 军备竞赛：成本来自算力，不来自「模型认不认得出」
- **滑块是体验**——它让「有验证码」这件事看得见，符合使用习惯。
  但滑块本身 ML + 轨迹重放可破，**不要把它当成安全边界**

不用 reCAPTCHA / hCaptcha：它们要连 Google / Cloudflare，而边缘门店那台
机器很可能根本不出网（[ADR-0015](0015-offline-first-hermetic.md)）。

## 后果

**得到的：**

- M8 能聚焦在它真正的价值上（params 表单生成），而不是先做半个身份系统
- 审计从「哪个 token 干的」变成「谁干的」，这一步的收益立刻兑现
- 不建空字段，将来做角色时是干净的起点

**代价（必须写进文档，不能只写在这里）：**

- **初始化之前存在抢注窗口。** mechd 默认监听 `0.0.0.0:8443`，从装完到有人
  完成初始化之间，**谁先打开那个页面谁就是管理员**。这是换自动化能力的直接
  代价。它在目标场景（离线/内网部署）里可接受；**若这台机器可能被公网扫到，
  就不要让它长时间停在未初始化状态**。
  缓解：初始化一次性（之后永久 409）、未初始化时启动即打 WARN、审计记来源 IP、
  与登录同一套限流。**刻意不做超时锁定**——部署到访问可能隔几小时，超时会把
  正常流程锁死，而唯一出路是回服务器敲命令，正好是这个方案要避免的
- **M8 之后，任何能登录 UI 的人都能做任何操作**——包括删组件、传 Pack、
  吊销节点。多人协作且需要权限隔离的场景，**在角色做出来之前不要开放 UI**
- **口令忘了只能在服务器上 `mechctl user passwd`**，或 `mechctl user reset`
  抹掉重来。后者会**重新打开初始化窗口**，这一点要在命令的确认里说清楚
- **PoW 挡不住慢速撞库**：一秒一次的人工尝试，算力成本可以忽略。
  真正挡住它的是按用户/按 IP 限流，两者缺一都不够
- **滑块不提供安全性**，只提供熟悉感。把它当成防护会高估整体强度
- PoW 让合法用户登录时多花约一秒 CPU；低端设备上会更久
- 没有口令找回：忘了只能在服务器上 `mechctl user passwd`。对边缘场景这
  反而是对的（找回流程需要邮件通道，而那又是一个外部依赖），但它是个真实
  的可用性缺口

**重新评估的条件：**

- 有用户提出「运维只能看不能改」这类需求时——那是角色划分真正被需要的信号，
  而不是现在凭空设计
- Site 模型本身稳定下来之后：Site 级授权是那三行草稿里最难的一半，
  它依赖 Site 边界先想清楚
